> 务虚不怕自说自话，怕的是停。这篇把一场对谈沉淀下来 —— 一条主线贯穿始终：**AI native 的硬标准，是「控制流交给谁」**：路径由人写死，还是由模型在推理里决定。

## 一、我们聊出来的认识

![AI Native：控制流交给模型、主动放弃确定性](/blogs/ai-native/f0acc2f79c38e15e.png)

### 1. 硬标准：控制流归属

判别一个产品是不是真 native，有个土办法：**「去掉 AI，它还成立吗？」**

- 拿掉 AI 后，回到一个**残缺但同质**的产品 → 那是 **AI-enabled**，AI 是增量装饰。
- 拿掉 AI 后，剩下一个**空壳**、交互范式整个垮掉 → 那才是 **AI-native**，AI 是本体。

更工程化的说法：**AI-enabled 的控制流由人写死（if-else、状态机、workflow，编译期定好）；AI-native 把控制流迁进了模型的推理里**——模型自己决定下一步、要不要再检索、调哪个工具、何时停。

![控制流对照：AI-enabled 固定管线 vs AI-native 模型循环](/blogs/ai-native/e02c2506250c8097.png)

由此引出一个反直觉的结论：**AI native = 主动放弃确定性。** 很多团队嘴上喊 native，身体却拼命把模型按回确定性的笼子，那其实没真迈过去。

### 2. 降级 ≠ 不是 native：两根不同的轴

「AI 挂了用户还能手动操作」是一条该守的工程纪律，但它属于**可用性轴**，不是**范式轴**。有降级路径 ≠ 不是 AI native。

关键看**降级之后还是不是同一个产品**：

- Perplexity 模型挂了能降级成「十条蓝链接」，但降级后的它**就是 Google**——那个「直接给答案」的产品已经不存在。退路上跑的是另一个物种。
- Google 加个 AI Overview，模型挂了撤掉框，**剩下的还是完整的 Google**。

> 真正的分水岭：降级后是回到一个残缺但同质的产品，还是回到一个完全不同的产品。前者 AI 是增量，后者 AI 是本体。

而且对**生成型 / 研究型**产品（让 agent 重构代码、整理五十篇论文的分歧点），「手动退路」这个概念本身会失效——因为它们做的事，人手动做要么做不到、要么慢到等于做不到。它们敢「孤注一掷」，是因为**甜区里根本不存在平价的手动替代品**。

### 3. Cloud Native 类比：好上车点，坏下车点

很多博文拿 cloud native 类比 AI native。这个类比是**好的上车点、坏的下车点**：

![Cloud Native 类比：借它上车，再踹掉梯子 —— 层级 / 确定性 / 成熟度三个骗局](/blogs/ai-native/6d2323594f5c9be6.png)
- **有效的一格**：`X native` 的共同语法是「别把旧范式假设搬到新基质上，要为新基质的原生特性重新设计」。「把虚拟机搬上云 vs 为云重构」正好对应「套个 API vs 围着模型重构控制流」。作为第一句话的教学工具，合格。
- **会骗你的三处**：
  1. **层级骗局**：cloud native 改的是「怎么跑」（运维层），AI native 改的是「是什么」（产品本体）。用运维范式类比本体范式，容易让人永远停在 enabled 还自以为 native。
  2. **确定性骗局**（最致命）：cloud native 自始至终是**完全确定**的；AI native 的唯一真特征——非确定性——在 cloud 世界里没有任何对应物。类比抹掉的，恰恰是唯一不能抹的东西。
  3. **成熟度骗局**：cloud native 有 CNCF、有 landscape、有 12-factor，是收敛的范式；AI native 还在前范式阶段。借词等于借了一身不属于它的体面，催生一堆「AI native 12 要素」式的过早编码。

> 好的写法：借 cloud native 讲清「native 是个什么动作」，然后立刻踹掉梯子——「但 AI 的原生特性是非确定性，从这里开始一切都不一样了」。

> **补一刀**：cloud native 当年也经历过「人人自称、十个九假」的泡沫期，最后是 CNCF 用一纸定义 + 一套可证伪的实践把词救回来的。AI native 现在缺的正是那个「可证伪的硬定义」——这也是为什么要把「控制流归属」死磕成唯一硬标准：**一个能证伪的标准，比一百个类比都顶用。**

### 4. 非确定性：唯一不能抹的属性

上一节踹梯子踹出来的那个东西，值得单独拎出来——因为它是 **AI native 唯一的真特征，也是 cloud native 世界里完全没有对应物的东西**。

cloud native 再复杂，`if` 还是 `if`，控制流还在代码里，系统**自始至终是确定的**。而一旦把控制流交给模型，你就同时签收了它的副作用：

> **AI native = 主动放弃确定性。** 你写完代码，根本不知道它下一步会干嘛——因为那取决于模型当时怎么想。相同输入未必给相同输出；甚至「重新生成同一个应用」都不保证行为一致。

![非确定性：相同输入经过概率过程，扇出 output A / A′ / A″](/blogs/ai-native/08c69fb5760d262b.png)

这件事改写了一整套工程世界观。确定性时代的全部美德——可测试、可复现、可回滚——都建立在「同样的输入 → 同样的输出」这个地基上。地基被抽掉后，**两种姿势分野**：

- **跟它对抗**：疯狂加 `if`、把 agent 退化成固定流程，把模型按回确定性的笼子。这是没真迈过去、只是焦虑——结果是个**穿了 native 外衣的 enabled**。
- **为它设计**：承认输出是概率的，转而在外面套**收敛机制**——evals、guardrails、人在回路、可解释与审计。不是消灭不确定性，而是**把它约束在可接受的带宽内**。

而这里有个**最关键、最容易被讲反**的判断：

> **确定性不是要被淘汰的旧东西，它是有价值的，而且是按任务性质分配的。**

- 一个支付系统、库存系统，你**最不想要**的就是「模型自己决定下一步」。这类任务，确定性是命根子，硬上 native 是负债。
- AI native 真正的甜区，是**那些本来就无法被穷举建模的任务**：开放域问答、代码生成、研究、创意。这些地方确定性本来就给不出来，所以放弃它没损失、反而解放。

所以「是不是该 native」不是技术先进性问题，是**任务性质匹配**问题。

这条非确定性的主线，往后会一路结账：它是「直接生成上生产」之所以危险的根因（兜底的闸被拆了）；是临时性下「重生成不保证一致」的来源；也是为什么人的工作会从**生产**转向**判断与验证**——因为一个概率系统，永远需要有人在出口处替它收敛。在工程上，这也把 **evals 从锦上添花顶成了一等公民**：你没法用断言测一个概率系统，只能用评估去**统计性地**信任它。

### 5. 开发范式：两次坍缩，性质完全不同

「老板认可、智能体直接生成上线」这件事，其实是**两件事同时塌了**，混在一起会害死人：

- **坍缩一：构建成本塌了。** 几小时串现成 API 出一个应用。这是**真的、不可逆的、好的**。
- **坍缩二：SDLC 纪律塌了。** 「不再测试环境验证 → 迭代 → 上生产，直接生成就上。」这**不是进步，是把风险管理一起扔了**。

AI 把构建成本打到地板，**并没有同时把支付系统、库存系统的「正确性要求」打到地板**。所以「直接生成上生产」对一次性小工具 OK，对系统级 record 是灾难。老板认可的是坍缩一的速度，默许的是坍缩二的省略——两笔账被速度合并成了一笔。

### 6. 各自为战：集成从此不再免费

过去三十年企业系统的「互联互通」，很大程度**不是靠好架构，而是靠「软件难做」本身当了强制粘合剂**：

任何系统都得过中央 IT → 研发是个瓶颈 → 但这个瓶颈**顺手**强制了集成（都接同一份主数据、同一个中台）。**集成是「建软件贵」这个摩擦力挤出来的副产品。**

AI 拆了瓶颈，门槛带走的那个集成副产品也没了——这是个典型的 **Chesterton 栅栏**：拆掉「中央研发瓶颈」时只看到它挡路，没看到它**同时在干集成这件活**。结果集成从「自动发生」变成「没人干」。

而 AI 让「构建」变便宜了，却**没让真正贵的协调成本变便宜**（谁的客户记录权威、跨系统一致性、治理审计、字段语义共识）。这些从来不是编码成本，是协调成本。

> 历史早演过：Excel 就是「非工程师建的一次性临时 app」，企业花三十年治理表格泛滥。**AI 生成的临时应用，是开了挂的电子表格。**

### 7. 临时性：软件分层剥离

软件「建得贵」的时代，可维护性、文档、测试、向后兼容**本质都是摊销机制**——让软件活得久、值回造价。当**重新生成比维护还便宜**，这套逻辑失去前提，软件从**耐用品**滑向**消耗品**。

但「全部临时」是错的。临时性会把软件**劈成两层**：

- **逻辑层 / 界面层 → 越来越临时**（能重生成，不值得养）
- **数据层 / 状态层 → 比以往更珍贵耐久**（独一无二，毁了就没了）

![临时性：软件分层剥离 —— 临时的逻辑/界面层，压在耐久的数据/规格层之上](/blogs/ai-native/fb2d39eac0daeac3.png)

最关键的一跃：**source of truth 从「代码」上移到「规格」**。代码能从 spec 重新生成，地位等同今天的编译二进制（没人把 `.o` 存进 git）。

> **Prompt / spec 成了新的源代码，代码成了新的二进制。** 工匠精神整体往上迁一层——别再让代码可维护，要让 spec、数据模型、集成契约清晰可重生成。

危险面：临时 × 非确定 = 重生成都不保证一致；叠加「各自为战」，临时 app 还会消失，没有稳定表面可供集成；代码这份「可读决策档案」消失，组织知识蒸发——除非被 spec 接住。

### 8. 代码能力：价值迁移，而非作废

「设计模式」与「DSA」在 AI 时代命运**几乎相反**：

- **设计模式**：本质是「给人看的、管理长期复杂度的沟通工具」。代码临时化后，对一段没有「下一个维护者」的牲口代码套 23 种模式，是给牲口做美甲。而且大半 GoF 模式本就是**语言缺陷的补丁**，AI 之前就在死。但模式底下的**边界判断力**不死，它上移到 spec / 架构层。
- **DSA**：是计算的物理，不是人类约定，**不贬值，而是发生两次位移**：
  1. **从「生产」迁到「判断」**：不再需要手写红黑树（AI 最擅长的教科书区，急速贬值），但**比以往更需要会读**生成代码、一眼判断「这是不是悄悄 O(n²)」。
  2. **从「均匀铺开」浓缩到「承重的 5%」**：临时层不在乎 DSA 优不优雅，承重层（热路径、核心结构）是 DSA 最要命处，且因周围液化而更突出。

> DSA 的价值，从「我能写出来」转成「我能看出生成的这段会死在哪」。

**代际陷阱——验证鸿沟**：通往「判断力」的路，过去是**穿过「生产」的苦功**修出来的。若新一代从不练手写、全交给 AI，就永远长不出验证 AI 所需的判断力——**你没法 review 你看不懂的东西**。基本功从来不只是为了生产，它是你**挣到判断力的学费**。

---

> ### ★ 贯穿全程的母题
>
> 这些「老东西」不是越来越没用——而是价值**从被 AI 吃掉的那一半（生产），迁移并浓缩到 AI 吃不掉的那一半（判断 · 承重层）**。出事的，永远是把硬层当软层、对该耐久的东西用快消逻辑的人。确定性、集成、耐久性、基本功——**不是越少越先进，而是按任务性质分配。**

## 二、基本展现形式

![基本展现形式：6 种形态按「控制流交出程度」爬楼梯，越往上越 native](/blogs/ai-native/057aa10c911e03b6.png)
用同一把尺子量：**控制流交给模型的程度**。从最 native，到最像剧场。

| # | 形态 | 含金量 | 代表 | 一句话 |
|---|------|--------|------|--------|
| 1 | **Agent / 编排** | 真 native | Cursor · Claude Code · Devin · Deep Research · computer use | 模型拥有循环，自己决定下一步、何时停。2026 唯一跑通生产的品类，首发是写代码（反馈强、能自验）。 |
| 2 | **Answer Engine / 生成式检索** | 半 native | Perplexity · ChatGPT search · Google AI Mode | 「给答案不给链接」。native 在交付物变了，但控制流较浅；deep research 才真往 agent loop 走。 |
| 3 | **Chat / 对话框** | 过渡形态 | ChatGPT · Claude 主界面 | 大众认知里的脸，但把「组织信息、决定下一步」甩回给用户，内行越来越判它为临时。 |
| 4 | **Copilot / 嵌入侧边栏** | 数量主流·含金量低 | M365 Copilot · Notion AI · Agentforce | 几乎每个 SaaS 都加了，也最低含金量——多数拿掉它产品照样完整。 |
| 5 | **Ambient / 后台 Agent** | 下一个主流 | background agent · async coding agent | 没有对话框、甚至没有前台。给个目标自己跑完回来报告。最彻底兑现「控制流交给模型」。 |
| 6 | **生成式媒体** | 另一根轴 | Sora · Midjourney · ElevenLabs | native 在「生成」而非「能动性」，模型是超强渲染器，没有控制流问题。属不同物种。 |

> **格局一句话**：数量上的主流是第 4 格（嵌入式 copilot，多半 enabled 装 native）；质量上、真正在定义 AI native 的，是第 1 格（agent）和正从它里面长出来的第 5 格（后台 agent）。中间的 chat 是大众的脸，但被判了「过渡」。

## 三、使用场景：甜区与雷区

「是不是该 AI native」不是技术先进性问题，是**任务性质匹配**问题（见 §4 非确定性）。一把判据就够：

> **问一句：这个任务能不能被穷举建模？**
> 能 → 确定性给得出来，别硬上 native，硬上是负债。
> 不能 → 确定性本来就给不出来，放弃它没损失——**这就是 native 的甜区。**

![使用场景天平：甜区(RAG/代码/研究/创意) vs 雷区(支付/合规/实时控制)，承重层确定、长尾层放开](/blogs/ai-native/2df4f7866de00a7a.png)

### ✅ 甜区：本来就无法被穷举建模的任务

| 场景 | 为什么是甜区 | 典型形态 |
|------|-------------|----------|
| **开放域 / 企业知识问答（RAG）** | 问题空间无限，没法预写所有 if；用户要的是综合答案而非翻文档 | Answer Engine / Agent |
| **代码生成与重构** | 反馈信号强（能编译、能跑测试），模型可自验，非确定性被确定性 oracle 兜住 | Agent / 后台 agent |
| **研究与综合** | 跨几十份资料找分歧点、做归纳——手动方式是「自己读完」，等于没有平价替代品 | Deep Research / Agent |
| **创意生成（文/图/音/视频）** | 没有唯一正确答案，「多样性」本身就是价值 | 生成式媒体 |
| **复杂工作流编排 / 长尾自动化** | 分支太多无法穷举，让模型按情况串工具比写死流程划算 | Agent / Ambient |
| **个性化 / 长尾客服交互** | 长尾意图无法枚举，确定性脚本永远漏 case | Copilot / Agent |

这些场景的共同点：**「手动退路」要么不存在，要么慢到等于不存在**——所以放弃确定性是解放，不是损失。

### ⛔ 雷区：要的就是确定性的任务

| 场景 | 为什么别 native | 该怎么办 |
|------|----------------|----------|
| **支付 / 清结算 / 账务 / 库存** | 系统级 record，错一笔有真实代价，必须可审计、可复现、可回滚 | 核心链路保持确定性；AI 只在**外围**（异常解释、对账辅助）增强 |
| **强合规 / 强一致场景** | 监管要求行为可预测、可解释、可追责 | 确定性主干 + AI 旁路，且人对结果负责 |
| **实时控制 / 错了无法人工兜底** | 非确定性 + 不可逆 = 不可接受 | 不上 native，或必须有确定性兜底闸 |

### 一个折叠规则

> 同一个系统里，**承重层（数据 / record / 热路径）保持确定**，**长尾层（开放交互 / 生成 / 研究）放开 native**。把这条线划错——对承重层用 native、对长尾层硬写死——是最常见、也最贵的错。

落到本项目（kb-mvp）：KB 问答**本体在甜区**，该往 Agent（Way B）方向押；但向量库里的 chunk、文档版本、KB 事实来源、eval 的 case 集与评分口径，是**碰不得的确定性承重层**——这条线就是产品该怎么搭的地图。

## 四、发展趋势

![发展主线：Chat → Copilot → Agent → Ambient，控制流从用户手里逐格交给模型](/blogs/ai-native/d4d85f79e873dadf.png)

| 维度 | 从 | 到 |
|------|----|----|
| 交互范式 | Chat | → Copilot → Agent → **Ambient 后台 agent** |
| 检索方式 | 预检索（固定管线） | **agentic 按需检索** |
| 商业模式 | 按座位 license | **按任务 / 按结果（outcome）**；软件从资产变用量 |
| 护城河 | 代码功能 | **数据 · 分发 · 信任 · 长期记忆 · 工作流嵌入** |
| 组织形态 | 人 + 人协作 | **少数判断者 + agent 群**；康威定律反转 |
| 人的角色 | 执行 / 生产者 | **审校者 + 意图提供者**；品味成为新稀缺 |
| 软件本体 | 指令式（确定指令） | **引导式（约束一个概率过程）** |
| 界面 | 固定 GUI | **可塑 / 生成式 UI**，每次为你即时长出来 |
| 集成 | 构建瓶颈的免费副产品 | **必须主动重建的协议层（MCP / 网关 / 主数据）** |

**贯穿主线**：`Chat → Copilot → Agent → Ambient` 就是控制流从用户手里**一格格交给模型**的过程。谁交得越多越 native。

三条要记住的判断：

- 势能在往 **Agent / Ambient** 走——谁把控制流交得越多，越 native。
- 碎片化会下沉到协议层：**应用层各自为战 + 协议层互联互通** 才是健康终态。
- 「集成不再免费」——组织里得有人为它**单独立项**，否则各自为战不是新范式，是没结账的债。
